# Изменения

## 30.10.2026 — расшифровка средствами Telegram

- Добавлен отдельный opt-in для одного голосового через нативный Telegram API и существующую пользовательскую сессию: ограничение действующими правами чтения, без загрузки аудио и сторонних провайдеров.
- Добавлены кэш частичных и готовых результатов, обработка `pending`, Telegram quota и FloodWait, а также защита от повторного запроса при неопределённом результате. BotFather остаётся недоступен агенту.
- На действующей установке один облачный агент запросил одно голосовое и получил готовую расшифровку после `pending`. Это не гарантирует качество текста, доступность остальных сообщений или объём квоты. Офлайн-тесты используют искусственные данные.

## 30.10.2026 — понятный старт и приватный ввод

- Добавлен короткий [маршрут владельца и агента](docs/start-here.md) и отдельная инструкция удалённого подключения без обязательной внешней поставки общего мастера.
- Скриншоты сняты с локальной страницы и искусственным состоянием; они не содержат действующих ключей, QR или переписки.
- Локальный launcher сообщает об устаревшем Python и ошибке открытия браузера. При ошибке браузера мастер закрывает сокет и удаляет только созданный им одноразовый handoff.
- Для отсутствующего общего мастера добавлен необязательный stdin/getpass helper: он сохраняет новый runtime key в приватный файл без вывода значения и без перезаписи. Хранение не доказывает авторизацию туннеля.
- Дополнена проверка опубликованного набора: она включает ранее добавленные опросы, BotFather, onboarding и PNG без метаданных.

## 29.10.2026 — подготовлены opt-in опросы

- Раздельные права на чтение, создание и закрытие своих опросов, точные цели или отдельный opt-in на все читаемые чаты и `request_id` с долговечными квитанциями.
- Readback фактического сообщения и защита от повторной отправки неопределённого результата; при чтении неизвестные голоса не превращаются в нули.
- Обычные опросы и викторины проверены синтетически с закреплённой версией Telethon. Настоящие отправка, закрытие и вызов конкретным облачным агентом требуют отдельной приёмки.

## 28.10.2026 — opt-in карточки, аватарки и вложения

- Чтение ограниченной карточки человека/чата, user avatar history и текущей group/channel avatar, просмотр и оригинальные Telegram bytes с хешем.
- `download_attachment` возвращает реальные binary bytes документов/фото, включая PDF больше 64 KiB; добавлены ресурсы и программный chunk fallback с проверкой размера/SHA и отзывом доступа.
- Отдельные read-only capabilities/actions и stdio flags поверх общего backend; прежние права, сессия и macOS режимы сохраняются. Реальная выдача конкретному агенту проверяется отдельно от синтетических тестов.

## Подготовлено локально 28.10.2026, не опубликовано: выбранные фотографии

- Opt-in `read-photo`: exact-source ACL, общий клиент Telegram, bounded staging, MIME/размер/TTL/хеш и отзыв доступа без смены сессии.
- `read_photo` с настоящим `ImageContent`, исходник через зарегистрированный MCP-ресурс и отдельный синтетический PNG probe.
- Синтетические unit и MCP stdio проверки; живая приёмка выбранного снимка существующим Dot остаётся отдельным этапом. Существующие режимы по умолчанию сохранены.

## 25.10.2026

- Подготовлен opt-in stdio MVP `send_saved_text`: только собственное «Избранное», отдельное право `send-saved-text`, обязательный request ID, приватная квитанция без текста и readback конкретного ID. Стандартный reader остаётся с шестью инструментами. Настоящая отправка через Dot пока не выполнялась.
- Локальный браузерный мастер: явный выбор возможностей, frozen bootstrap, вход по обновляемому QR или телефону/коду, скрытый ввод 2FA и настоящий MCP status. Loopback, временный доступ страницы, Origin/Host, no-store/CSP и pipes без вывода секретов. Добавлены исходный Mac launcher и генератор Linux-ярлыка; системные prerequisites подготавливаются отдельно.
- Исправлена передача выбранной приватной директории, managed backend и локального proxy через subprocess SDK в MCP-клиенте и reader gateway. Скрытый Terminal-ввод больше не блокирует Telegram event loop.
- 115 тестов macOS/Linux и отдельная живая приёмка Linux reader: ограниченное чтение двумя SDK-клиентами, запреты записи/чужого чата, отзыв и restart/checkpoint. Настоящий dot-плагин, внешний маршрут и живой GUI-login пока не считаются проверенными.
- Reader gateway для прямых подключений dot и других агентов: шесть MCP tools для статуса, диалогов, контактов, истории, поиска и недавних сообщений. Произвольная передача команд upstream и запись не открываются.
- Отдельные bearer-токены, отзыв/срок действия, разрешённые чаты и контакты, отдельный выбор всех чатов/контактов и телефонных полей. Смена прав проверяется до каждой операции, включая ожидающие запросы.
- MCP Streamable HTTP на loopback с аутентификацией каждого запроса, ограничением Origin/Host и размера тела; stdio-профиль для Secure MCP Tunnel. Публичный незащищённый listener не добавлен.
- `read_dialog_page`: ограниченные страницы метаданных с курсором и архивом, без загрузки всей истории. Инкрементальные сообщения продолжают использовать `read_history_page` и checkpoint.
- Linux persistent backend, managed relay без запуска конкурирующего процесса, выключенные systemd units с backoff и staging без авторизации/копирования сессии.
- Синтетические проверки реального HTTP и stdio MCP, двух клиентов, областей доступа, отзыва, запрета записи, restart/checkpoint и FloodWait. Живой аккаунт Linux и вызов через dot проверяются отдельно; macOS-установка сохраняется.
- Инструкция Linux, примеры Codex/Claude и пустой безопасный реестр агентов.

## 23.10.2026

- Один локальный backend Telegram и отдельные stdio MCP-сессии для нескольких чатов; автоматическое завершение после отключения всех клиентов и завершения инвентаризации.
- `mcp_client.py`: проверка существующего подключения, список/схема tools и вызов с параметрами из JSON без отдельной авторизации.
- `read_history_page`: ограниченные страницы истории с курсором и верхней ID-границей, без скачивания вложений.
- `read_owned_inventory`: группы/каналы с признаком владельца, архив, мигрировавшие группы и собственные боты; продолжение сканирования и соблюдение FloodWait.
- Инструкция обновления общей установки, образец передачи другим агентам и проверка переноса заметок до удаления исходников.
- Conversation Guard сохраняется в режиме локального snapshot/draft: реальные чтения/утверждения/отправки и обещание OS-изоляции не добавлены.
- Guard 0.2.0 отклоняет прежние live-политики. Старый credentialed upstream и production dispatch выключены; `--require-isolation` отказывает до загрузки состояния. Независимый обзор Claude ещё не завершён.
- Изменение или потеря файла разрешений блокирует новые вызовы уже работающего backend до перезапуска. Незавершённая инвентаризация сохраняет процесс между клиентами, чтобы не терять курсор во время FloodWait.
