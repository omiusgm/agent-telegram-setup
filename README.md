# Ёж Telegram MCP — личный Telegram для агента

Экспериментально подготовлены opt-in [список своих ботов, создание и уведомления владельцу](docs/owned-bots.md). Они выключены по умолчанию и проверены только на синтетических данных, без создания настоящего бота. Удалённый фасад исключает переписку BotFather и фильтрует распознаваемые токены; [границы защиты](docs/botfather-output-guard.md) не включают OS-изоляцию.

Подготовлены opt-in [опросы для удалённого агента](docs/polls.md): чтение результатов, создание и закрытие своих опросов с отдельными правами, выбранными целями и readback. Доступ ко всем читаемым чатам настраивается отдельно. Проверены синтетические MCP-сценарии; включение и реальный вызов конкретного облачного агента принимаются отдельно.

Добавлены opt-in [карточки и аватарки](docs/peer-profiles.md) и [скачивание настоящих вложений](docs/attachments.md) для удалённого агента: отдельные права чтения, ImageContent и binary MCP resources с SHA-256. Перед использованием проверяется конкретная установка и получение байтов клиентом; наличие исходников не означает активацию в каждом подключении.

Подготовлено opt-in чтение [выбранных фотографий для удалённых агентов](docs/selected-photos.md): отдельные права на точные сообщения, `ImageContent` для просмотра и исходные байты через MCP-ресурс с SHA-256. По умолчанию выключено; реальная доставка пикселей существующему Dot проверяется отдельно от локальных тестов.

Готовое решение Владимира. [Единый каталог «Агент Ёж»](https://github.com/omiusgm/agent-ezh-catalog) · [Gmail и Яндекс Почта](https://github.com/omiusgm/agent-mail-setup).

Инструкция для клиента и его агента: подключить **свой личный Telegram** через локальный MCP, войти один раз и проверить реальное чтение. Основа — [chigwell/telegram-mcp](https://github.com/chigwell/telegram-mcp), закреплённая ревизия `e55d9c7a66a8eb0855debb268a4ed5b63749af2d` (v3.2.97), Telethon и небольшая локальная обёртка.

**Подключение к личному Dot:** [пошаговый гайд с учебными иллюстрациями](docs/dot-client-guide.md) · [короткое задание агенту](docs/dot-agent-handoff.md) · [индекс картинок по блокерам](docs/dot-guide-steps.json). Маршрут: Telegram MCP → OpenAI Secure MCP Tunnel → личный plugin → настоящий вызов Dot. Общий браузерный setup использует существующий Telegram-компонент; [контракт](docs/setup-flow-contract.md) не добавляет второй UI.

Подготовлено по рабочей настройке, проверенной на **macOS 27.0, Apple Silicon, Python 3.11**. Добавлен Linux reader gateway: установка и offline-проверки выполняются отдельно от авторизации аккаунта и проверки dot. Windows не поддерживается. Это стороннее подключение, не официальный продукт Telegram или OpenAI.

Обновление 23.10.2026: несколько локальных чатов используют одно подключение, добавлены MCP-клиент для агентов, чтение истории порциями и инвентаризация собственных групп, каналов и ботов. [Изменения](CHANGELOG.md) · [Проверки](docs/verification.md).

Обновление 25.10.2026: [общий Linux-сервис для dot и других агентов](docs/linux-service.md). Отдельные отзываемые доступы, разрешённые чаты/контакты, только чтение, MCP Streamable HTTP с bearer-аутентификацией на loopback и stdio для защищённого туннеля. Текущая macOS-настройка сохраняется; живой вход Linux, внешний маршрут и вызов dot требуют отдельной приёмки.

Подготовлен [минимальный stdio MVP отправки текста в «Избранное»](docs/saved-text-mvp.md): команда `send_saved_text`, отдельное право агента, защита от повторной отправки и проверка текста чтением обратно. По умолчанию отправка выключена; живая отправка из Dot ещё не проверена.

Обновление 28.10.2026: профили, аватары и опциональные настоящие вложения через gateway. Скачивание в облачный клиент проверяйте отдельно; лимит gateway 5 МБ. Вступление по ссылке — эксперимент с отдельным подтверждённым запросом владельца, не часть обычного профиля чтения. [Вложения](docs/attachments.md) · [Каналы по поручению](docs/requested-sources.md).

## Личный аккаунт или бот

| Задача | Подключение | Граница доступа |
|---|---|---|
| Читать свои личные диалоги, искать в доступной истории | Личный аккаунт через MTProto, этот пример | Права авторизованного аккаунта; доступные операции ограничивает сервер |
| Получать обращения отдельному боту, работать в добавленной группе | Bot API, токен от BotFather | Бот не получает произвольную личную переписку владельца |

Bot token не заменяет API ID / API Hash и пользовательскую сессию. MCP — интерфейс для агента; он сам по себе не выдаёт разрешений Telegram.

## Что подготовить

- Компьютер Mac с Git, Python 3.11+ для запуска установщика и [uv от Astral](https://docs.astral.sh/uv/getting-started/installation/). Установщик создаёт отдельную `.venv` с Python 3.11.
- Telegram на телефоне с действующим входом. При включённой двухэтапной защите понадобится ваш пароль.
- Собственные API ID и API Hash: откройте [my.telegram.org/apps](https://my.telegram.org/apps), затем **API development tools**. Название приложения, например `Personal Assistant`, короткое имя `personalassistant`, платформа Desktop. Соблюдайте [условия API Telegram](https://core.telegram.org/api/terms).

Ключи, номер, код входа и пароль вводятся владельцем локально. Не отправляйте их в чат с агентом и не используйте опубликованные чужие сессии.

## Установка и вход

Для владельца добавлен [мастер на localhost](docs/web-setup.md): выбор возможностей, установка зависимостей проекта, QR или телефон/код, скрытый ввод 2FA и проверка MCP в браузере. На Mac в папке проекта есть `TelegramSetup.app`; на Linux агент подготавливает ярлык. Git, uv и Python 3.11+ предварительно готовит устанавливающий агент; настоящий вход через новый GUI и Finder-launcher ещё требуют проверки. Ниже сохранён способ через Terminal.

```bash
git clone https://github.com/omiusgm/agent-telegram-setup.git
cd agent-telegram-setup
python3.11 bootstrap.py
.venv/bin/python -m telegram_setup.login
```

При первом запуске установщик **спросит, какие возможности разрешить агенту**: просмотр и скачивание вложений, расшифровку голосовых, отправку текста и файлов, пересылку, редактирование, удаление и порядок в чатах. Выберите нужные пункты; для расшифровки отдельно выбирается способ распознавания. Если настройку ведёт агент, он сначала задаёт этот вопрос вам. [Полный список и изменение прав](docs/permissions.md).

Установщик загружает закреплённый upstream и применяет его lockfile через `uv sync --frozen`. Выбранные права сохраняются в `.local/permissions.json`. Он не меняет текущие настройки MCP и не ищет другие установленные Telegram-сессии. При повторном запуске сохранённый выбор и изменённый upstream не перезаписываются автоматически.

В Terminal появится QR. На телефоне откройте **Telegram → Настройки → Устройства → Подключить устройство**. Сканируйте оттуда, не обычной камерой. Истёкший код обновится автоматически. Если Telegram попросит пароль двухэтапной защиты, введите его в скрытом запросе Terminal.

Если терминальный QR плохо читается:

```bash
.venv/bin/python -m telegram_setup.login --qr-image
```

Откройте `.local/login-qr.png` локальным просмотрщиком и обновляйте изображение после сообщения об обновлении кода. Файл удаляется при завершении входа. QR действует ограниченное время и тоже является секретом входа. Альтернатива — скрытый ввод телефона и кода:

```bash
.venv/bin/python -m telegram_setup.login --phone
```

Устройство появится в Telegram как **Personal Agent MCP**. Последующие запуски используют сохранённую сессию.

## Подключить MCP к Codex

Из корня этого репозитория:

```bash
codex mcp add telegram-personal -- "$PWD/.venv/bin/python" "$PWD/server.py"
codex mcp get telegram-personal
```

Если сервер с таким именем уже существует, сначала посмотрите его настройку. Сохраните прежнюю запись и обновите только нужный сервер. Не заменяйте весь `config.toml`. [Образец конфигурации](examples/mcp-config.toml) содержит только условные пути, без ключей; [официальная документация OpenAI](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) описывает актуальные параметры.

Перезапустите MCP или начните новый сеанс агента. Попросите показать доступные инструменты Telegram, вернуть несколько диалогов и прочитать одно выбранное вами сообщение. Локальный сервер доступен клиенту на этом компьютере; облако и другой компьютер не получают его автоматически.

Набор команд определяется вашим выбором при установке. Его можно изменить без нового входа: `.venv/bin/python -m telegram_setup.permissions`; посмотреть — той же командой с `--show`. Без явного выбора новая установка не продолжается автоматически с урезанным профилем.

API Hash хранится в `.local/credentials.json`, сессия — в `.local/account.session`; каталог имеет права 700, файлы — 600 и исключены из Git. Это файловая защита, не шифрование: процессам вашего пользователя и администратору файлы могут быть доступны. Сессия позволяет входить в аккаунт без нового кода, поэтому её нельзя публиковать или передавать между агентами.

## Проверить результат

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python verify_mcp.py --all-permissions
```

Это проверки на синтетических данных: QR-порядок, истечение кода, ветка 2FA, приватные файлы, блокировка сессии, профили инструментов и настоящий MCP stdio handshake. Offline-сервер в тесте блокирует Интернет-соединения и не проверяет вход в ваш Telegram.

После вашего входа отдельно проверьте реальное чтение:

```bash
.venv/bin/python verify_mcp.py --live
```

Команда выводит только статус и количества, не имена, ID чатов или сообщения. Она не отправляет сообщения и обращается к тому же общему процессу, поэтому работающий MCP останавливать не нужно.

## Доступ из других локальных чатов

Одна установка и одна авторизация обслуживают несколько MCP-клиентов. `server.py` запускает лёгкий stdio relay; сессию Telegram открывает только общий локальный процесс. Не копируйте файлы авторизации в другие проекты. Все чаты этой установки используют один выбранный набор прав.

Если нативные инструменты не загрузились в конкретном чате, агент может обратиться к тому же MCP из любого рабочего каталога:

```bash
"/absolute/path/agent-telegram-setup/.venv/bin/python" \
  "/absolute/path/agent-telegram-setup/mcp_client.py" status
```

Для этого замените условные пути на пути установки. `status` выполняет маленькое чтение `get_me` и выводит только статус и наличие команд. Клиент также показывает схему инструмента и принимает параметры из локального JSON. [Общий процесс, остановка и обновление](docs/shared-connection.md).

Рабочая исходная настройка прошла реальное чтение; новая установка каждого клиента требует собственной проверки. Подробности: [что проверено](docs/verification.md).

## Возможности и ограничения

- Подготовлены [scoped-поиск и файлы в «Избранном»](docs/scoped-search-and-files.md): быстрые страницы полного аккаунта, обязательный ID fan-out для ограниченных агентов, отдельные публичные метаданные, временное хранилище и проверка файлов скачиванием обратно. По умолчанию выключены; полная бинарная приёмка файла у настоящего Dot выполняется отдельно.

- Каталог публичных источников и событий можно хранить отдельно от личных контактов: [правила хранения, проверки и обновления](docs/knowledge-catalog.md), [JSON-схема](examples/knowledge-catalog.schema.json). Это формат данных для агентов; расписание мониторинга включается отдельно.
- Экспериментальный режим для вступления в источники по сообщению владельца описан в [инструкции](docs/requested-sources.md). Он требует отдельного доверенного обработчика сообщений агента и пока не включается универсальным мастером.
- Список доступных диалогов, поиск, чтение сообщений, контактов и доступных медиа — в пределах прав аккаунта и опубликованных инструментов upstream.
- Скачивание вложений, просмотр документов и фото, отправка текста, файлов и другие действия выбираются отдельно: [права](docs/permissions.md), [отправка и файлы](docs/sending.md). Включённая возможность позволяет выполнять соответствующие поручения владельца.
- Нет доступа к Secret Chats. Удалённые сообщения не восстанавливаются; история ограничена тем, что Telegram отдаёт этому аккаунту.
- Голосовые расшифровываются по запросу, если выбрана эта возможность и настроен способ распознавания. Картинки и документы доступны при выборе просмотра вложений; сохранение на диск включается отдельно.
- `read_history_page` читает историю последовательно с курсором и границей снимка, без скачивания вложений. `read_owned_inventory` собирает группы/каналы с признаком владельца и ботов из Telegram API, включая архив. [Формат и ограничения](docs/history-and-inventory.md).
- Несколько локальных MCP-клиентов делят один процесс аккаунта. Постоянный мониторинг, фоновые рассылки и обход лимитов не включаются. Шифрование MTProto не означает, что прочитанные агентом сообщения остаются только на устройстве: они могут попасть в контекст выбранного AI-сервиса.

Выбранные права реализованы фильтрацией инструментов сервера, а не отдельными узкими правами Telegram. Сессия по-прежнему принадлежит личному аккаунту. Для жёсткой изоляции процессов/данных нужен отдельный проект безопасности.

## Если агент будет самостоятельно вести переписки

Перед делегированием агент должен предупредить о prompt injection из сообщений собеседника. Текущая локальная ревизия Guard допускает **только снимок и черновики**: исходный Telegram-клиент, approval API, шаблонные автоответы и внешние записи в этом режиме выключены. Старый live-запуск без подтверждённого runtime закрыт.

[Граница Reader / credentials broker / Writer и запуск](docs/conversation-guard.md) · [Исследование](docs/prompt-injection-research.md).

OS-изоляция не развёрнута. У чата с терминалом, исходным Telegram MCP или другими обходными инструментами доступ сохраняется; он не становится secure от одного профиля. `--require-isolation` сейчас отказывает. Обычная Telegram-интеграция и глобальные настройки клиента не переключаются автоматически.
