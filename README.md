# Агент Ёж · личный Telegram для AI-агента

Готовое решение Владимира. [Единый каталог «Агент Ёж»](https://github.com/omiusgm/agent-ezh-catalog) · [Gmail и Яндекс Почта](https://github.com/omiusgm/agent-mail-setup).

Инструкция для клиента и его агента: подключить **свой личный Telegram** через локальный MCP, войти один раз и проверить реальное чтение. Основа — [chigwell/telegram-mcp](https://github.com/chigwell/telegram-mcp), закреплённая ревизия `e55d9c7a66a8eb0855debb268a4ed5b63749af2d` (v3.2.97), Telethon и небольшая локальная обёртка.

Подготовлено по рабочей настройке, проверенной 21.10.2026 на **macOS 27.0, Apple Silicon, Python 3.11**. Публичный пакет устанавливается и тестируется отдельно, без подключения чужого аккаунта. Windows не поддерживается этим примером; Linux использует сходные механизмы, но здесь не проверен. Это стороннее подключение, не официальный продукт Telegram или OpenAI.

## Личный аккаунт или бот

| Задача | Подключение | Граница доступа |
|---|---|---|
| Читать свои личные диалоги, искать в доступной истории | Личный аккаунт через MTProto, этот пример | Права авторизованного аккаунта; доступные операции ограничивает сервер |
| Получать обращения отдельному боту, работать в добавленной группе | Bot API, токен от BotFather | Бот не получает произвольную личную переписку владельца |

Bot token не заменяет API ID / API Hash и пользовательскую сессию. MCP — интерфейс для агента; он сам по себе не выдаёт разрешений Telegram.

## Что подготовить

- Компьютер Mac с Git, Python 3.11+ для запуска установщика и [uv от Astral](https://docs.astral.sh/uv/getting-started/installation/). Установщик создаёт отдельную `.venv` с Python 3.11.
- Telegram на телефоне с действующим входом. При включённой двухэтапной защите понадобится ваш пароль.
- Собственные API ID и API Hash: откройте [my.telegram.org/apps](https://my.telegram.org/apps), затем **API development tools**. Название приложения, например `Personal Assistant`, короткое имя `personalassistant`, платформа Desktop. Соблюдайте [условия API Telegram](https://core.telegram.org/api/terms).

Ключи, номер, код входа и пароль вводятся владельцем локально. Не отправляйте их в чат с агентом и не используйте опубликованные чужие сессии.

## Установка и вход

```bash
git clone https://github.com/omiusgm/agent-telegram-setup.git
cd agent-telegram-setup
python3.11 bootstrap.py
.venv/bin/python -m telegram_setup.login
```

Установщик загружает закреплённый upstream и применяет его lockfile через `uv sync --frozen`. Он не меняет текущие настройки MCP и не ищет другие установленные Telegram-сессии. При повторном запуске изменённый upstream не перезаписывается автоматически.

В Terminal появится QR. На телефоне откройте **Telegram → Настройки → Устройства → Подключить устройство**. Сканируйте оттуда, не обычной камерой. Истёкший код обновится автоматически. Если Telegram попросит пароль двухэтапной защиты, введите его в скрытом запросе Terminal.

Если терминальный QR плохо читается:

```bash
.venv/bin/python -m telegram_setup.login --qr-image
```

Откройте `.local/login-qr.png` локальным просмотрщиком и обновляйте изображение после сообщения об обновлении кода. Файл удаляется при завершении входа. QR действует ограниченное время и тоже является секретом входа. Альтернатива — скрытый ввод телефона и кода:

```bash
.venv/bin/python -m telegram_setup.login --phone
```

Устройство появится в Telegram как **Personal Agent MCP**. Последующие запуски используют сохранённую сессию.

## Подключить MCP к Codex

Из корня этого репозитория:

```bash
codex mcp add telegram-personal -- "$PWD/.venv/bin/python" "$PWD/server.py"
codex mcp get telegram-personal
```

Если сервер с таким именем уже существует, сначала посмотрите его настройку. Сохраните прежнюю запись и обновите только нужный сервер. Не заменяйте весь `config.toml`. [Образец конфигурации](examples/mcp-config.toml) содержит только условные пути, без ключей; [официальная документация OpenAI](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) описывает актуальные параметры.

Перезапустите MCP или начните новый сеанс агента. Попросите показать доступные инструменты Telegram, вернуть несколько диалогов и прочитать одно выбранное вами сообщение. Локальный сервер доступен клиенту на этом компьютере; облако и другой компьютер не получают его автоматически.

По умолчанию выставлен профиль **read-only**. API Hash хранится в `.local/credentials.json`, сессия — в `.local/account.session`; каталог имеет права 700, файлы — 600 и исключены из Git. Это файловая защита, не шифрование: процессам вашего пользователя и администратору файлы могут быть доступны. Сессия позволяет входить в аккаунт без нового кода, поэтому её нельзя публиковать или передавать между агентами.

## Проверить результат

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python verify_mcp.py
```

Это проверки на синтетических данных: QR-порядок, истечение кода, ветка 2FA, приватные файлы, блокировка сессии, профили инструментов и настоящий MCP stdio handshake. Offline-сервер в тесте блокирует Интернет-соединения и не проверяет вход в ваш Telegram.

После вашего входа отдельно проверьте реальное чтение:

```bash
.venv/bin/python verify_mcp.py --live
```

Команда выводит только статус и количества, не имена, ID чатов или сообщения. Она не отправляет сообщения. На время проверки остановите **свой** работающий MCP этой установки, затем запустите его снова. Если не хотите останавливать сервер, проверьте чтение через уже подключённые инструменты агента.

Рабочая исходная настройка прошла реальное чтение; новая установка каждого клиента требует собственной проверки. Подробности: [что проверено](docs/verification.md).

## Возможности и ограничения

- Список доступных диалогов, поиск, чтение сообщений, контактов и доступных медиа — в пределах прав аккаунта и опубликованных инструментов upstream.
- Отправка текста, ответа и выбранного файла может быть включена отдельным профилем: [отправка и файлы](docs/sending.md). Включённая возможность не является постоянным разрешением пользоваться ею.
- Нет доступа к Secret Chats. Удалённые сообщения не восстанавливаются; история ограничена тем, что Telegram отдаёт этому аккаунту.
- Голосовые и изображения не становятся текстом автоматически. В этом примере транскрибация отключена; выбранные вложения требуют отдельного скачивания/распознавания по задаче.
- Не обещаем постоянный онлайн-мониторинг, фоновые рассылки, обход лимитов или несколько параллельных процессов на одной сессии. Шифрование MTProto не означает, что прочитанные агентом сообщения остаются только на устройстве: они могут попасть в контекст выбранного AI-сервиса.

Ограничение read-only реализовано фильтрацией инструментов сервера, а не отдельными узкими правами Telegram. Сессия по-прежнему принадлежит личному аккаунту. Для жёсткой изоляции процессов/данных нужен отдельный проект безопасности.
