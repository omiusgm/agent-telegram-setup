# Одно подключение для нескольких локальных чатов

`server.py` — stdio relay. При первом обращении он запускает `telegram_setup.shared`; следующие клиенты подключаются к тому же процессу через Unix socket. Только backend открывает сессию и держит `client.lock`. Каждый клиент получает отдельную MCP-сессию, общие права и файловый корень этой установки.

Авторизация остаётся в `.local/` либо в явно заданном `AGENT_TELEGRAM_HOME`. Socket находится в коротком каталоге `/tmp/agent-telegram-<uid>-<installation-hash>/`: каталог 700, socket 600. Короткий путь нужен из-за ограничения Unix socket на macOS. Там нет API-ключей или копии сессии. TCP/HTTP-сервер не запускается. Это доступ локального пользователя ОС, а не изоляция от других его процессов.

Отключение одного клиента не разрывает другие соединения. Через 10 секунд после отключения всех клиентов backend завершается, удаляет socket и освобождает блокировку, если нет незавершённой инвентаризации. Незавершённый проход, в том числе пауза FloodWait, удерживает процесс и курсор между вызовами. Пока хотя бы одна MCP-сессия открыта, завершения из-за простоя тоже нет. Фоновая очередь отправок этим транспортом не добавляется.

## Запасной клиент для агентов

Используйте абсолютные пути, если рабочий каталог другого чата отличается. Примеры ниже выполняются из корня установки:

```bash
.venv/bin/python mcp_client.py status
.venv/bin/python mcp_client.py tools send_file
.venv/bin/python mcp_client.py tools download_media
.venv/bin/python mcp_client.py call get_messages --args-file /absolute/path/request.json
```

`tools ИМЯ` показывает фактическую JSON Schema; поля параметров берите из неё. JSON содержит рабочие параметры MCP, без API Hash, паролей или session. Ответы `call` могут содержать личную переписку: не публикуйте их. `status` проверяет связь через `get_me`, скрывая имя, телефон и ID. Клиент не читает credentials и не создаёт собственный Telethon-клиент.

Ошибку или timeout отправки нельзя считать доказательством отсутствия сообщения. Сначала проверьте получателя и историю, затем решайте, нужен ли повтор. Клиент автоматически не повторяет вызовы.

## Применить изменение прав или обновить код

1. Завершите незаконченный read_owned_inventory либо отмените его параметром cancel=true (это только локальное состояние). Сохраните настройки прав, не меняя авторизацию. Существующий выбор при обновлении сохраняется. Перед каждым новым вызовом backend сверяет выбор с настройками запуска: изменение, удаление или повреждение файла прав блокирует вызов до операции. Старый список tools может ещё отображаться, но команды со старыми правами не выполняются.
2. Отключите MCP **этой установки во всех использующих её клиентах**. Изменение или повреждение файла прав немедленно блокирует последующие вызовы старого backend до перезапуска, но не отменяет уже начатую операцию. Один новый чат не загружает новый набор tools в работающий процесс.
3. Подождите не менее 10 секунд после последнего отключения. Дождитесь освобождения `client.lock`; не завершайте процесс во время активной передачи. Если права не менялись, сначала завершите незаконченный проход инвентаризации. Явная смена прав снимает удержание незавершённого прохода и позволяет idle-завершение; следующий процесс начинает инвентаризацию заново.
4. Для Git-checkout выполните `git pull --ff-only`, затем `python3.11 bootstrap.py`. При локальных изменениях сначала рассмотрите diff; не используйте `reset --hard`. Не копируйте приватные файлы в новый checkout.
5. Подключите MCP снова, проверьте `mcp_client.py status`, нужную схему и `.venv/bin/python verify_mcp.py --live`.

Те же остановка и ожидание нужны перед повторным `telegram_setup.login`. При обычном чтении через клиент или `verify_mcp.py --live` останавливать backend не нужно. Диагностический запуск `python -m telegram_setup.server` использует отдельный эксклюзивный stdio-режим и конфликтует с работающим shared backend; используйте штатный `server.py`.

Приватный `.local/shared-server.log` рассматривайте только локально: upstream может записывать туда операционные детали. Не прикладывайте полный лог к публичным issues. При ошибке запуска проверьте этап, путь установки и тип ошибки, не удаляя сессию.

Облако, Linux-агент на другом компьютере и чужой пользователь ОС не наследуют этот socket. Не открывайте его в Интернет и не передавайте auth key. Их подключение требует отдельного решения и проверки.
