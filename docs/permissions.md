# Выбор прав Telegram MCP

При первой установке `bootstrap.py` спрашивает, какие возможности дать агенту. Если настройку ведёт Codex, Claude Code или другой агент, он сначала задаёт этот вопрос владельцу, затем передаёт согласованный выбор установщику. Пустой ответ не считается выбором. Автоматическая установка без Terminal требует явного списка прав.

Чтение — базовая возможность. Остальные пункты можно сочетать независимо: например, скачивание вложений без отправки сообщений или отправка файлов без редактирования истории.

| Выбор | Что разрешает | Команды MCP |
|---|---|---|
| `read` | Читать диалоги, сообщения, контакты, искать, получать метаданные и свои группы/каналы/ботов | Инструменты чтения upstream, `read_history_page`, `read_owned_inventory`, без отключённых возможностей ниже |
| `media` | Показывать фото, читать содержимое выбранных документов и изображений | `inspect_document`, `open_photo`, `get_photo_sheet`, `get_user_photos` |
| `download` | Сохранять выбранные вложения на компьютер | `download_media`, `preview_custom_emoji` |
| `transcribe` | Расшифровывать голосовые и видеокружки выбранным способом | `transcribe_voice` |
| `send-text` | Отправлять текст и ответы | `send_message`, `reply_to_message` |
| `send-files` | Загружать и отправлять документы, картинки, альбомы, голосовые, видео, стикеры и GIF | `send_file`, `send_album`, `send_voice`, `upload_file`, `send_sticker`, `send_gif` |
| `forward` | Пересылать выбранные сообщения | `forward_message`, `forward_messages` |
| `edit` | Редактировать доступные аккаунту сообщения и черновики | `edit_message`, `save_draft`, `clear_draft` |
| `delete` | Удалять сообщения, отложенные сообщения и историю, в том числе пакетно | `delete_message`, `delete_messages_bulk`, `delete_chat_history`, `delete_scheduled_message` |
| `organize` | Отмечать прочитанным, архивировать, менять уведомления, закрепления и папки | Соответствующие команды чатов и папок; точный список — в `telegram_setup/permissions.py` |

Скачивание включает документы, фото, видео и аудио: форматы обслуживает одна команда `download_media`. Отправка разных форматов тоже объединена в одну возможность. Просмотр вложения внутри контекста агента и сохранение вложения на диск выбираются отдельно. Запрет `download` ограничивает команды сохранения файлов MCP; это не изоляция файловой системы самого AI-клиента.

Права сессии Telegram шире опубликованного набора MCP. Эта настройка фильтрует инструменты сервера; правила и дополнительные ограничения клиента также могут сужать доступ. Изменение участников, прав групп и настроек аккаунта не входит в перечисленные группы.

## Изменить права без нового входа

```bash
.venv/bin/python -m telegram_setup.permissions
.venv/bin/python -m telegram_setup.permissions --show
```

Выбор хранится в `.local/permissions.json` с правами 600. Авторизация и API-ключи этим шагом не меняются. После изменения отключите MCP этой установки во всех клиентах, подождите не менее 10 секунд после последнего отключения, затем подключите снова и проверьте реальный `list_tools`. После изменения файла прав старый backend блокирует новые вызовы до перезапуска; уже начатая операция не отменяется. Каталог tools обновляется при новом запуске. [Подробности перезапуска](shared-connection.md).

Агент может сохранить уже согласованный выбор явно:

```bash
.venv/bin/python -m telegram_setup.permissions --allow read,media,download,send-text,send-files --yes
```

Для первоначальной установки без Terminal используется тот же список:

```bash
python3.11 bootstrap.py --permissions read,media,download,send-text,send-files
```

Готовые наборы доступны через `--preset`: `read-only` — только чтение; `reader` — чтение, просмотр и скачивание; `assistant` — то же плюс текст и файлы. Они выбираются владельцем явно, не применяются вместо его ответа. Пересылка, редактирование, удаление и организация чатов в эти наборы не входят.

Старые значения `AGENT_TELEGRAM_ACCESS=read-only/send-text/send-files` поддерживаются, если нового файла выбора ещё нет. Сохранённый набор прав имеет приоритет над старым профилем; лучше убрать старую переменную из MCP-конфигурации, чтобы не было двух описаний настроек. Повторная установка сохраняет существующий выбор, пока владелец не попросит его изменить.

## Голосовые и транскрипции

Если включена расшифровка, установщик отдельно предлагает выбрать один способ:

- `telegram`: встроенное распознавание Telegram. Доступность и лимиты зависят от аккаунта. Проверяйте ответ сервера; включённая команда не доказывает наличие необходимой подписки.
- `whisper`: локальный faster-whisper. Установщик добавляет extra `whisper`; модель может отдельно скачиваться при первом использовании. Скорость и ресурсы зависят от компьютера.
- `groq`: аудио отправляется в Groq. Нужны собственный `GROQ_API_KEY`, доступная квота и согласие на передачу выбранного аудио этому сервису.
- `openai`: аудио отправляется на OpenAI-совместимый endpoint. До включения агент уточняет конкретный сервис и адрес; задаются `TELEGRAM_TRANSCRIBE_OPENAI_URL` и при необходимости `TELEGRAM_TRANSCRIBE_OPENAI_API_KEY`, `TELEGRAM_TRANSCRIBE_OPENAI_MODEL`. Совместимость протокола не означает, что сервер принадлежит OpenAI.

Способ сохраняется вместе с правами. Вызов с другим `engine` отклоняется до обращения к провайдеру. Режим всегда on-demand: новые расшифровки появляются по запросу, фоновое распознавание всех голосовых не включается.

```bash
.venv/bin/python -m telegram_setup.permissions --allow read,download,transcribe --transcription-engine telegram --yes
```

Команда возвращает текст и использует кэш upstream. Если пользователь просит TXT с расшифровкой, агент сохраняет полученный текст как локальный файл; отдельной Telegram-команды «скачать транскрипт» нет. Для исходного аудиофайла нужен `download`. Качество распознавания проверяется отдельно: машинная расшифровка может содержать ошибки.

При переключении существующей установки на локальный Whisper установите дополнительные зависимости в ту же среду:

```bash
UV_PROJECT_ENVIRONMENT="$PWD/.venv" uv sync --project .upstream --frozen --no-dev --extra proxy --extra whisper --python 3.11
```

Ключи провайдеров владелец задаёт локально; агент не просит их в чате и не публикует. Offline-проверки не обращаются ни к Telegram, ни к сервисам распознавания.

## Проверка выбранных возможностей

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python verify_mcp.py --all-permissions
```

Матрица проверяет настоящий MCP initialize/list_tools для каждой группы и сочетаний. Не выбранная команда скачивания также проверяется прямым вызовом: сервер обязан отклонить её. Для транскрипции проверяется запрет смены провайдера. Это проверка настроек и протокола на синтетических данных; реальное скачивание, отправка и распознавание требуют отдельной проверки на выбранном материале владельца.

Включённая возможность означает, что агент может выполнить соответствующую задачу. Конкретные действия с аккаунтом выполняются по поручениям владельца; ранее данное ясное поручение не требует повторного разрешения только из-за наличия MCP.
