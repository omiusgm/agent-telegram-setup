# Диагностика

Не публикуйте полный лог, дамп окружения, QR, credential/session-файлы или скриншоты с кодами. Достаточны ОС, pinned commit, профиль, этап и тип ошибки. Сетевые проверки начинайте без авторизации; не перебирайте чужие прокси.

| Симптом | Что проверить / сделать |
|---|---|
| `Too many attempts` на my.telegram.org | Прекратить повторные попытки и дождаться снятия ограничения Telegram. Это ограничение сайта, не отсутствие Telegram MCP. Не брать чужой API Hash или сессию. |
| Неверный QR | Открыть в Telegram «Настройки → Устройства → Подключить устройство». Использовать только свежий код из текущего процесса. Если вход уже дошёл до запроса 2FA, QR принят — нужен пароль. |
| `SessionPasswordNeededError` | Ввести пароль двухэтапной защиты в Terminal. Это не SMS-код и не пароль macOS. Не присылать его агенту. |
| `ApiIdInvalidError` | Владелец проверяет пару API ID / API Hash у собственного приложения. Не печатать их для диагностики. |
| `PhoneCodeInvalidError` / `PhoneCodeExpiredError` | Код вводит владелец локально; не повторять запросы кодов циклически. |
| `FloodWaitError` | Подождать сообщённое Telegram число секунд. Сохранять checkpoint и продолжать последовательно, не обходить лимит параллельными клиентами. |
| `Сессия уже используется` / SQLite locked | Штатные клиенты используют общий `telegram_setup.shared`. Перед повторным login или эксклюзивным запуском отключите их все и подождите не менее 10 секунд. Проверьте путь установки; не создавайте второй Telethon-клиент и не завершайте чужие процессы. |
| `AuthKeyDuplicatedError` | Остановить все подтверждённые копии этой сессии. Не разносить auth key по компьютерам/IP. Владелец проверяет устройства и при необходимости отзывает старую сессию, затем делает новый локальный вход. |
| Timeout / ConnectionReset | Проверить сеть и работающий VPN. Успешный TCP connect ещё не доказывает MTProto-вход. Не отключать firewall/TLS и не менять системный маршрут вслепую. |
| MCP есть, tools не видны | Проверить абсолютные пути и настройки сервера. Запустите `mcp_client.py status` и `tools ИМЯ`. После смены прав требуется завершить общий backend отключением всех его клиентов; один новый чат не обновляет уже работающий процесс. `verify_mcp.py` offline проверяет регистрацию, `--live` читает через общий процесс. |
| Пустой поиск | Проверить правильный чат, период и пагинацию; сначала получить несколько сообщений из истории без текстового фильтра. Не объявлять данные отсутствующими по одному запросу. |
| Не найден пользователь / entity | Найти диалог через list_chats, использовать возвращённый ID. Новый ID не всегда разрешается без актуального entity cache; не выдумывать username/ссылку. |

## Уже работающий локальный SOCKS5

В одной проверенной сети временные MTProto-сбои обходились существующим локальным SOCKS. Позднее прямое соединение снова заработало. Это не универсальное требование Telegram.

После выбора маршрута владельцем компьютера узнайте фактический порт. Ниже **условный** пример, он не настраивает VPN:

```bash
AGENT_TELEGRAM_SOCKS_HOST=127.0.0.1 AGENT_TELEGRAM_SOCKS_PORT=1080 \
  .venv/bin/python -m telegram_setup.login
```

Те же две переменные нужны в MCP config для сервера и live-проверки. Пример поддерживает только явно указанный локальный SOCKS без пароля. Если он недоступен, скрытого перехода на прямой маршрут нет. Системный HTTP/PAC-прокси не означает, что Telethon использует его; переменные HTTP_PROXY сами по себе не заменяют настройку MTProto/SOCKS.

## Отключить доступ

Остановите MCP этой установки. В Telegram откройте «Настройки → Устройства» и завершите нужную сессию **Personal Agent MCP**. После этого удаление локальных файлов по запросу владельца — отдельная уборка; само по себе удаление файла не отзывает удалённую авторизацию. Не удаляйте чужие устройства и не уничтожайте все сессии аккаунта.

Несколько локальных клиентов поддерживаются через один процесс и приватный Unix socket. [Устройство и перезапуск](shared-connection.md). Не публикуйте его по HTTP в Интернет ради доступа с другого компьютера.
