# Подключение через браузер без ввода команд

Мастер открывается на `127.0.0.1` на вашем компьютере. В нём можно выбрать возможности, подготовить окружение, ввести собственные API ID/Hash, войти по QR или телефону/коду, ввести пароль 2FA и проверить настоящий ответ MCP. Терминальный вход остаётся альтернативой.

Это Telegram-компонент общего setup, а не полный мастер OpenAI-туннеля. Раздел runtime key и итоговый единый маршрут ведёт общий мастер Telegram/Codex; [контракт интеграции](setup-flow-contract.md). Сам по себе результат `verified` этой страницы не подтверждает polling, установку plugin или вызов Dot. [Полный клиентский путь](dot-client-guide.md).

## Для владельца

Устанавливающий агент сначала проверяет, нет ли уже работающего Telegram MCP. Если он есть, новый вход обычно не нужен. Для новой установки агент подготавливает Git, uv и Python 3.11+ и сохраняет остальные настройки клиента. Мастер не устанавливает эти системные зависимости сам.

На Mac откройте `TelegramSetup.app` в папке проекта через Finder. Это исходный локальный launcher, не подписанный универсальный установщик; запуск через Finder и правила macOS необходимо проверить на конкретной машине. На Linux агент может подготовить ярлык `.desktop`; поддержка запуска зависит от рабочего стола. Владелец затем проходит шаги в браузере:

1. **Возможности.** Отметьте нужное и нажмите «Подготовить MCP с выбранными правами». Уже сохранённый выбор показывается при повторном запуске. Для расшифровки способ выбирается отдельно; модель, адрес и ключ внешнего распознавания настраиваются отдельно агентом по согласованному выбору.
2. **Вход.** Если ключей ещё нет, получите своё приложение на [my.telegram.org/apps](https://my.telegram.org/apps) и введите API ID/Hash здесь. Далее выберите QR или телефон/код. QR сканируется из Telegram → Настройки → Устройства → Подключить устройство, обновляется автоматически и исчезает после перехода к 2FA. Код и пароль вводятся в скрытых полях мастера.
3. **Проверка.** Кнопка проверяет MCP initialize, каталог и чтение служебной информации аккаунта. Она не отправляет сообщения и не выгружает переписку. После успеха устанавливающий агент подключает этот MCP к нужному клиенту, сохраняя его прочие настройки.

Закройте мастер его кнопкой. При перезагрузке страницы одноразовый ключ доступа теряется — откройте мастер через ярлык снова. Это не удаляет Telegram-сессию и не требует нового входа в аккаунт. Мастер также автоматически закрывается через 30 минут.

## Для устанавливающего агента

GUI запускается без Telethon в стартовом интерпретаторе; зависимости авторизации загружаются в отдельную `.venv` существующим frozen bootstrap. Не подменяйте выбранные владельцем права. Не запускайте новую установку поверх действующего backend ради проверки.

```bash
python3 setup_web.py --open
```

Для общего Linux reader используйте режим, в котором нельзя выбрать запись:

```bash
AGENT_TELEGRAM_HOME="$HOME/.local/share/agent-telegram-mcp" \
  .venv/bin/python setup_web.py --open --reader-only
```

Ярлык Linux создаётся установщиком в новый файл, без перезаписи существующего:

```bash
python3 scripts/create_linux_launcher.py \
  --output "$HOME/Desktop/Telegram-Setup.desktop" --reader-only
```

Для headless Linux владелец использует браузер своего компьютера через согласованный SSH port forward. Мастер остаётся на loopback; локальный и удалённый порты должны совпасть, чтобы не менять проверки Host/Origin. Агент запускает мастер с `--no-open --port PORT --connection-file ПРИВАТНЫЙ_НОВЫЙ_ФАЙЛ` и подготавливает защищённое открытие владельцу. Файл должен находиться непосредственно в `AGENT_TELEGRAM_HOME`; он создаётся с правами 600, содержит только временный URL мастера и удаляется при завершении. URL с одноразовым fragment-токеном не печатайте в чат и журналы. Не открывайте этот интерфейс на LAN/public address и не извлекайте авторизацию из браузера.

Активный backend сохраняет блокировку сессии. Мастер не останавливает его сам: сначала используйте проверку готового MCP. Для повторного входа или смены возможностей потребуется согласованный перезапуск именно этой установки.

## Граница безопасности и готовности

- Listener только `127.0.0.1`; изменение данных требует временного bearer-токена страницы, точных Host/Origin и JSON. Размер тела ограничен, CORS не открывается; ответы `no-store`, CSP без внешних скриптов.
- Пароли, OTP и QR передаются рабочему процессу через приватные pipes, не через аргументы команд. QR живёт в памяти. Пароль/OTP не сохраняются. Сохраняются только API-конфигурация и стандартная Telegram-сессия в прежней приватной директории.
- Общая блокировка защищает от конкурирующих Terminal/GUI/backend процессов. FloodWait показывает паузу и блокирует новую попытку в этом мастере. Сессия при ошибках не удаляется автоматически.
- GUI не публикует MCP, не создаёт API-ключи OpenAI, не регистрирует remote plugin и не выдаёт права удалённому агенту. Для этого есть [Linux-инструкция](linux-service.md).
- Синтетически проверены настоящий HTTP UI, запреты Origin/Host/авторизации, лимит тела, обмен с рабочим процессом через pipes, смена QR, ввод/повтор 2FA и ветка телефона/кода. В браузере проверены навигация, выбор способа расшифровки и формы на искусственных данных. Настоящий Telegram-вход через GUI и запуск ярлыка через Finder ещё не проверены; рабочая авторизация Linux отдельно проверена через Terminal и MCP.

Windows этим POSIX-пакетом не поддерживается. Same-UID shell и администратор остаются вне границы защиты локального мастера; это не OS-изоляция.
