# Dot MVP: один текст в собственное «Избранное»

Подготовлено 25.10.2026. Это минимальное дополнение к Linux reader: одна команда `send_saved_text`, отдельное право агента и проверка результата чтением обратно. Новая Telegram-сессия не создаётся. OAuth, аппаратная привязка и Conversation Guard не требуются для этой разовой проверки владельцем. Они не объявляются реализованными.

## Что открывается

- По умолчанию сохраняются шесть read-only tools. Только stdio с `--enable-saved-text` показывает седьмой tool; HTTP reader остаётся read-only.
- Агенту отдельно выдаётся действие `send-saved-text`. Ни флаг запуска, ни право сами по себе не включают отправку без второго условия и выбранного backend `send-text`.
- Получатель зафиксирован сервером: `me`, собственное «Избранное». Аргументов `chat_id`, `account`, файлов, пересылки или форматирования нет; дополнительные параметры отвергаются до вызова upstream.
- Текст: от одного непустого символа до 4096 единиц UTF-16. `request_id`: 8–128 символов из букв ASCII, цифр и `_.-`.
- До отправки создаётся приватная квитанция с отпечатком текста, без самого текста. Повтор того же ID/текста возвращает прежнюю квитанцию без новой отправки; другой текст с тем же ID отклоняется.
- `delivered_verified` означает, что конкретный ID сообщения прочитан обратно из «Избранного» и текст совпал. Потерянный ответ, неизвестный ID или несовпадение чтения дают `uncertain_do_not_retry`: новый ID для повтора создавать нельзя, сначала нужен осмотр владельцем.

## Подготовка не является активацией

Сейчас код и искусственные проверки подготовлены. Настоящая отправка через Dot ещё не выполнялась. Существующие сессия, реестр агентов и read-only службы не переключаются установкой исходников. Platform, туннель и runtime credential подготавливаются одним оператором, без параллельных входов и создания ключей.

После готовности параметров туннеля оператор отдельно активирует разрешённый владельцем тест на Linux. Следующие команды — будущие действия, а не команда пользователю повторно войти:

```bash
cd ~/services/agent-telegram-mcp
export AGENT_TELEGRAM_HOME="$HOME/.local/share/agent-telegram-mcp"
export AGENT_TELEGRAM_MANAGED_BACKEND=1
systemctl --user stop agent-telegram-reader.service agent-telegram-backend.service
.venv/bin/python -m telegram_setup.permissions --allow read,send-text --yes
.venv/bin/python -m telegram_setup.agents grant-saved-text dot
systemctl --user start agent-telegram-backend.service
```

Дождитесь приватного socket и успешного `mcp_client.py status`, затем запустите `agent-telegram-reader.service`. Проверка должна показывать `send_file=false`; никакие сообщения на этом этапе не отправляются. Смена набора прав требует остановки/старта общей службы, но не нового Telegram login.

Stdio-команда туннеля: те же абсолютные пути установки, `AGENT_TELEGRAM_HOME`, `AGENT_TELEGRAM_MANAGED_BACKEND=1` и:

```bash
.venv/bin/python gateway_server.py --transport stdio --agent dot --enable-saved-text
```

Контроль из самого Dot: семь tools, `telegram_status.connected=true`, `send_saved_text_allowed=true`, `send_text_backend_ready=true`. Успешный SDK initialize не заменяет вызов Dot. Секрет runtime key остаётся только на сервере; в команду передаётся поддерживаемая file/env reference, не значение.

## Один будущий live-тест

С подтверждением владельца в Dot выполнить ровно один вызов:

```json
{"text":"Тест Telegram MCP из Dot — 25.10.2026","request_id":"dot-saved-mvp-20261025-001"}
```

Ожидается `destination=saved_messages`, `status=delivered_verified`, положительный `message_id`, `readback_verified=true`. Проверить сообщение в «Избранном». Не запускать этот тест из setup-агента вместо Dot и не повторять с новым request ID после неопределённого результата.

Отзыв только отправки, без отключения чтения:

```bash
.venv/bin/python -m telegram_setup.agents revoke-saved-text dot
```

Полный отзыв остаётся `agents revoke dot`. Перезапуск шлюза без `--enable-saved-text` снова оставляет шесть инструментов. Для возврата backend к первоначальному набору после остановки служб выберите `permissions --allow read --yes` и снова запустите их.

## Проверки и пределы MVP

Искусственно проверены: отказ reader до upstream, независимые права, отзыв ожидающего запроса, фиксированный получатель, plain text, точное чтение ID/текста, повтор после восстановления состояния, запись claims до отправки, неопределённый результат без автоматического повтора, настоящий stdio MCP с семью tools и запрет подмены получателя.

Это не автономная переписка с людьми. Отправки в другие чаты, файлы, редактирование, удаление и read receipts этим MVP не открываются. Внутренний backend при активации получает `send-text`, но внешняя команда остаётся только для «Избранного»; процесс с полным shell того же Linux UID может обойти фасад. Изоляция от владельца/администратора хоста и полноценный Conversation Guard находятся за пределами этой проверки.
