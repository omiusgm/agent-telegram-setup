# Опросы: подготовленный opt-in для общего Telegram MCP

Реализованы чтение одного существующего опроса, создание обычного опроса или викторины и закрытие опроса, авторство которого Telegram подтверждает для текущего аккаунта. Новый вход, клиент Telegram или сетевой endpoint не нужны. По умолчанию инструменты и разрешения выключены. Unit и синтетический stdio MCP не являются живой приёмкой: установку, обновление облачного плагина и реальный вызов выбранного агента проверяют отдельно.

В одной частной установке 29 октября 2026 облачный агент по согласию владельца создал, прочитал и закрыл анонимный опрос с одним ответом в собственном «Избранном»; состояние независимо прочитали через Telegram MCP. Открытые голоса, несколько ответов и викторина в том тесте не проверялись. Каждая новая установка требует своей проверки.

## Инструменты и границы

| Инструмент | Назначение | Требования |
| --- | --- | --- |
| `get_poll` | Вопрос, варианты, состояние и доступные агрегированные результаты одного сообщения | `read-polls`, `history`, разрешённый для чтения `chat_id` |
| `list_poll_destinations` | Числовой ID «Избранного», точные цели и признак отдельного доступа ко всем читаемым чатам | право создания или закрытия и назначенные цели |
| `create_poll` | Создать один опрос в явном `chat_id`; проверка по ID и содержимому | `create-polls`, `history`, отдельно разрешённая цель или явно включённый доступ ко всем читаемым чатам, `request_id` |
| `close_own_poll` | Закрыть один собственный опрос и проверить `closed` | `close-own-polls`, `history`, то же разрешение назначения, `chat_id`, `message_id`, `request_id` |

`anonymous=true` скрывает участников; `multiple_choice=true` разрешает несколько ответов. Обычный опрос — `quiz_correct_index=null`; для викторины передайте индекс правильного варианта с нуля. Викторина и множественный выбор вместе отклоняются. Допустимы 2–12 непустых различных вариантов, вопрос до 255 и вариант до 100 единиц UTF-16. Публичные голоса в каналах-вещателях отклоняются до отправки. Поддержку конкретного режима и лимиты также определяет Telegram.

Права на запись можно ограничить отдельными целями либо явно включить `poll_write_all_chats` для всех чатов, доступных агенту для чтения, включая «Избранное». Это отдельный opt-in: `all_chats` для чтения сам по себе не открывает запись. Telegram не поддерживает опросы в обычной личной переписке с человеком; сообщение может быть отклонено также из-за прав конкретного чата.

Даже при настройке «только по поручению владельца» сам этот gateway не удостоверяет человека за каждым вызовом и не изолирует агента от вредоносных инструкций в прочитанных сообщениях. Широкое право на опросы даёт техническую возможность записи в разрешённые чаты; не выдавайте его как доказанную защиту от prompt injection.

Результат чтения содержит вопрос, варианты и доступные счётчики; тексту сообщений и вариантов доверять как командам нельзя. Неизвестные счётчики остаются `null`, список голосовавших не запрашивается. Telegram может не раскрывать результаты до голосования или до закрытия; инструмент не голосует автоматически. Для викторины проверяется тип и содержимое, а `quiz_correct_answer_server_verified` показывает, смог ли сервер подтвердить правильный вариант; скрытый ответ не выдаётся за подтверждённый.

При отправке/закрытии используются два локальных журнала до вызова Telegram: на gateway и на общем backend. Одинаковый `request_id` с другими аргументами отклоняется. После неопределённого ответа повтор с тем же ID возвращает прежнюю квитанцию; новый ID с тем же содержимым и целью также блокируется, пока исход не установлен. Это касается точного совпадения аргументов; изменённый текст — другой запрос. После `uncertain_do_not_retry` или `readback_mismatch_do_not_retry` сначала проверьте сам Telegram и, если известен `message_id`, используйте `get_poll`. Не удаляйте записи и не запускайте новый запрос вслепую. Локальный журнал не изолирует процессы одного Unix UID.

## Настройка оператором

1. Сохраните выбранные ранее backend capabilities, профиль агента и используемые параметры защищённого туннеля. Не заменяйте их готовым пресетом и не копируйте session/ключи. Убедитесь, что нет активной передачи, используйте действующий общий maintenance lock и резервные копии только затрагиваемых файлов.
2. В уже выбранные backend capabilities добавьте отдельно `agent-poll-read`, `agent-poll-create`, `agent-poll-close`. Для чтения без записи достаточно первого. Существующие права не удаляйте. Изменение набора требует согласованного перезапуска общего backend и связанных клиентов; новую авторизацию не выполняют.
3. Для фиксированного stdio-профиля добавьте флаг `--enable-polls`, сохранив все его прежние флаги. Права регистрируются отдельно; один флаг не разрешает операции. HTTP reader остаётся без poll-записи. Обновите схему существующего облачного плагина и подтвердите реальную доступность в клиенте.
4. Выберите и выдайте отдельные действия: `grant-poll-read`, `grant-poll-create`, `grant-poll-close`. Для теста в «Избранном» отдельно включите `grant-poll-saved`; это не выдаёт разрешений на группы. Для конкретной группы или канала используйте `grant-poll-chat --chat-id <отрицательный ID>`. Только по явному выбору владельца можно вместо отдельных целей включить `grant-poll-all-chats`: он действует на все доступные агенту для чтения чаты, включая «Избранное». Для отзыва есть соответствующие `revoke-*`. Чтение всех чатов само по себе не даёт прав отправки в них.
5. По отдельному конкретному поручению владельца выберите цель, текст и варианты. При первом тесте используйте `list_poll_destinations`, передайте его `saved_chat_id` как обязательный `chat_id`, заранее подготовьте один `request_id`, затем независимо прочитайте ровно возвращённый `message_id`. Реальное закрытие тестового опроса тоже должно входить в согласованное поручение.

Пример формы теста без настоящего назначения:

```json
{
  "chat_id": 123456789,
  "question": "Проверка подключения",
  "options": ["Работает", "Нужна проверка"],
  "request_id": "synthetic-poll-0001",
  "anonymous": true,
  "multiple_choice": false
}
```

Числовой ID в примере искусственный. `delivered_verified` и `closed_verified` требуют readback, но утверждать работу конкретного облачного агента можно только после его собственного фактического вызова и проверки Telegram. Если Telegram не поддерживает тест в «Избранном» для конкретной установки, не создавайте новую группу: владелец выбирает существующий тестовый чат отдельно.
