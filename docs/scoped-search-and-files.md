# Scoped-поиск и файлы в «Избранном»

Локальная реализация проверяется синтетическим stdio MCP. Вызов новых команд
настоящим Dot и создание нового облачного файла требуют отдельной приёмки.
Новые login, сессия, ключ или туннель не нужны.

## Поиск

Флаг `--enable-search` добавляет команды к существующим чтению и Saved text:

| Команда | Результат | Право |
|---|---|---|
| `search_allowed_messages` | Сообщения из разрешённых диалогов с продолжением | `search` |
| `search_public_communities` | Публичные метаданные групп/каналов | отдельное `public-search` |

При `all_chats=false` запрашиваются только `chat_ids`; перехода к глобальному
поиску при ошибке нет. При `all_chats=true` используется ограниченный MTProto
`messages.searchGlobal`: одна страница индекса и одна проверка только найденных
диалогов через `messages.getPeerDialogs`. Перечисление всех диалогов не требуется.
В ответ допускаются сообщения существующих основных/архивных диалогов с историей;
посторонние, вышедшие/деактивированные или непроверяемые peers не возвращаются.
Auxiliary users/chats из Telegram не выдаются списком контактов. `channels.searchPosts`,
старый upstream `search_global` с повторным чтением префикса и autojoin не используются.

Параметры: `query`, `cursor`, `limit` (1–100), `request_budget` (1–20, default 10).
Для полного аккаунта вызов всегда ограничен одной backend-страницей и максимум
двумя Telegram RPC по 20 секунд. Для restricted бюджет ограничивает fan-out.
Бюджет ограничивает один вызов, а не охват аккаунта. Продолжайте `next_cursor`,
в том числе после пустой страницы. Приватный курсор живёт час, сохраняется при
перезапуске и привязан к агенту, запросу, размеру страницы и правам. Сужение прав
его отменяет. Полный аккаунт хранит offsets `rate/peer/id` только на сервере;
клиент получает opaque `a2:` cursor. Повтор продолжения возвращает сохранённую
страницу без новых RPC. Старый cursor, который только собирал каталог и не выдавал
сообщений, мигрирует на быстрый поиск. После уже выданных сообщений нужен новый запрос.

`complete=true` означает завершение всех чатов без ошибок; иначе смотрите `errors`
и `scan_finished`. FloodWait сохраняет позицию: выдержите `retry_after_seconds`.
Restricted-поиск фиксирует верхний ID каждой переписки. Полный аккаунт фиксирует
верхнюю дату индекса, учитывает `next_rate`, дедуплицирует `(chat_id, message_id)`
и не считает короткую slice последней страницей. Это не атомарный снимок Telegram.
`inexact=true` не означает полного покрытия; изменения/удаления отдельно не сверяются.
Если страница превышает 1.2 MB, вернётся `account_search_page_exceeds_byte_limit`:
начните запрос без cursor с меньшим limit. Промежуточный offset не выдумывается.

Публичный поиск не возвращает пользователей, ботов, телефоны, участников, историю
или приватные приглашения. Вступления не выполняются. Telegram выдаёт ранжированные
совпадения без устойчивой пагинации; полнота мирового каталога не обещается.

При неудачной проверке `telegram_status` поле `connection_error` содержит безопасную
категорию. `telegram_cooldown` требует выдержать `retry_after_seconds`;
`upstream_read_failed` требует проверить существующий backend и маршрут;
`unexpected_status_payload` указывает на неожиданный формат ответа.
`connected=false` означает, что проверка `get_me` не подтвердила подключение,
и само по себе не подтверждает отзыв авторизации. Новую сессию ради этого не создают.

## Файлы

Для stdio с фиксированным агентом `--enable-saved-files` добавляет:

| Команда | Вход → результат |
|---|---|
| `stage_file` | Нативный host file object, размер и SHA-256 → `staging_id` |
| `stage_text_file` | Ограниченный вариант: UTF-8 текст → временный документ |
| `send_saved_file` | `staging_id`, durable `request_id`, подпись → квитанция Telegram |
| `download_saved_file` | ID документа в «Избранном» → MCP resource |
| `get_staged_file_resource` | Повтор своего скачанного ресурса до TTL |

`stage_file` объявляет `_meta["openai/fileParams"]=["file"]`. У объекта обязательны
строковые `download_url` и `file_id`, необязательны `mime_type` и `file_name`;
все четыре свойства объявлены. HTTPS, обычная проверка TLS, точный allowlist хостов,
публичные DNS/IP и закрепление адреса соединения обязательны. Редиректы, proxy из
окружения и локальные адреса запрещены. URL и внешний file ID не сохраняются.
Allowlist пуст по умолчанию; оператор добавляет точный хост через `--file-host`.

Предел: 5 MiB на файл, TTL 15 минут, до 8 активных файлов на агента. Каталоги 700,
файлы 600. Инструменты принимают случайный opaque ID, а не путь. На каждом доступе
проверяются агент, upload/download, TTL, размер и SHA-256. `stage_text_file`
принимает до 64 KiB UTF-8 и расширения `.txt`, `.md`, `.csv`, `.json`. Создание
документа из текста не доказывает передачу нативного облачного вложения.

Существующий backend использует фиксированный `InputPeerSelf`. Оригинал отправляется
как документ. Backend получает настоящий message ID и скачивает файл обратно,
сверяя байты, размер, имя, MIME и подпись. Только затем выдаются
`status=delivered_verified` и `readback_verified=true`. До отправки сохраняются
durable-квитанции gateway и backend. Потеря ответа или несовпадение дают
`uncertain_do_not_retry`: автоматический повтор с новым ID запрещён.

## Права и отзыв

Backend требует возможности `saved-files`; широкие `send-files` и `download`
не нужны. Агенту отдельно выдаются `send-saved-file`, `download-saved-file`.
При ограниченных чатах собственный Saved ID также должен быть разрешён.

Операторские команды после согласования конкретного набора:

```bash
python -m telegram_setup.agents grant-public-search AGENT
python -m telegram_setup.agents grant-saved-upload AGENT
python -m telegram_setup.agents grant-saved-download AGENT
```

Для отзыва замените `grant-` на `revoke-`. Остальные поля и права сохраняются.
Отзыв проверяется перед запросом и после ожидания. Уже начатую отправку нельзя
отозвать задним числом. Resource URI после отзыва не даёт доступа. Изменение
backend permissions требует согласованного перезапуска соответствующих сервисов.

## Получение файла Dot

Для проверки без файловых grants есть временный stdio-флаг `--enable-file-probe`.
Команда `file_transport_probe` без аргументов возвращает фиксированный синтетический
TXT: никаких Telegram-запросов, файловой системы или внешних URL внутри команды.
Root проверяет новый файл у настоящего Dot; после приёмки флаг удаляется.

До 64 KiB ответ содержит стандартный `EmbeddedResource`/`BlobResourceContents`,
больше — `ResourceLink`. URI принадлежит реально зарегистрированному MCP-ресурсу
с `resources/read` и теми же ACL/TTL. Это не публичный endpoint, облачная ссылка
или ChatGPT file ID. Входной file ID не используется как результат скачивания.

Offline-клиент получает исходные байты обоими способами. Создание нового файла
у Dot отдельно не подтверждено: `dot_file_received_verified=false`. Приёмка:
исходный файл Dot → Linux → Telegram → свежее скачивание → новый файл Dot,
одинаковые размер и SHA-256. Base64 в тексте, путь Linux и квитанция upload
не заменяют эту проверку.

Источники: [OpenAI File APIs](https://developers.openai.com/plugins/reference#file-apis),
[Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels),
[MCP tools/resources](https://modelcontextprotocol.io/specification/2025-06-18/server/tools).
Проверенный исходный контракт Harpoon возвращает HTTP-тело в JSON `body_base64`;
это не создание нового файла у Dot. Harpoon в этой версии не включается.
