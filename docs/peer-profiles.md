# Карточки и аватарки удалённому агенту

Opt-in read-only набор поверх существующего общего backend. Новая сессия, Bot API, публичная файловая ссылка и отдельный Telegram-клиент не нужны.

Три уровня: installation capability `agent-profiles`, stdio-флаг `--enable-profiles`, отдельные agent actions `read-profiles`/`read-avatars`. Существующие чаты, контакты, `include_phones`, токены, сроки и прочие агенты сохраняются. По умолчанию набор выключен.

Команды агента:

| Инструмент | Результат |
| --- | --- |
| `get_peer_profile(peer)` | Доступные имя, username, описание, текущий avatar ID и ограниченная карточка человека/группы/канала |
| `list_avatars(peer,offset,limit)` | История видимых пользовательских аватарок, либо текущая аватарка группы/канала |
| `read_avatar(peer,photo_id)` | Реальный ImageContent preview и metadata исходника с SHA-256 |
| `get_avatar_original(staging_id)` | Рабочий ACL/TTL-bound MCP resource исходных байтов |

`peer` — числовой ID из разрешённой области. При полном peer-scope разрешены также точный @username и `me`; ограниченный профиль не может использовать username для обхода ACL. Явные `contact_ids` входят в область карточек. `all_contacts` без `all_chats` не открывает произвольные числовые ID. Телефоны возвращаются только при уже выбранном `include_phones`.

Фото не нужно вручную разрешать по одному: `read-avatars` действует в существующем peer-scope. Это не фоновая выгрузка всех людей. Отзыв action или peer-scope запрещает также чтение сохранённых ресурсов. Удалить ранее полученные агентом байты таким отзывом нельзя.

Пределы исходника/preview, staging root, TTL 15 минут и agent quota наследуются от файлового слоя. Исходник связан с agent/peer/photo ID и проверяется чтением/SHA. Нет произвольных путей/URL/account/agent в инструментах. User avatar history читается порциями до 25 записей; для групп/каналов этот срез предоставляет текущую фотографию без сканирования переписки. Telegram может ограничить видимость аватарок настройками приватности.

Оригинал означает Telegram JPEG-представление, а не исходный файл камеры. `actual_agent_pixels_verified` и `native_cloud_file_verified` сервер всегда оставляет false: они требуют внешней приёмки настоящим агентом. Стандартный MCP resource не является доказательством появления облачного downloadable artifact.

Смена аватарок/имени/описания, сторис, переписка с людьми, read receipts и администрирование этим набором не включаются. Добавлять действия записи нужно отдельно по конкретному поручению. Текущий full-text search и Saved text сохраняются, если были включены ранее.

Оператор после согласия владельца использует `telegram_setup.agents grant-profiles AGENT` и `grant-avatars AGENT`; отзыв — `revoke-profiles`/`revoke-avatars`. Изменение installation snapshot требует согласованного перезапуска общего backend, а изменение agent actions перечитывается на запросах. Нельзя менять snapshot посреди активной передачи.

Синтетические проверки: `test_peer_profiles.py` и настоящий stdio SDK с `test_peer_stdio.py`; реальные Telegram/Dot проверки фиксируются отдельно.
