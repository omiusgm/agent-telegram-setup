# Conversation Guard v0: делегирование одного диалога

Это экспериментальный отдельный MCP-модуль для случая «веди переписку за меня». Обычное чтение, подготовка файлов и разовые отправки по поручению владельца продолжают работать через основной Telegram MCP. Включение Guard не меняет их автоматически.

При делегировании агент должен коротко предупредить владельца: собеседник может поместить в сообщение инструкции для агента. Затем предложить защищённый режим и согласовать диалог, срок и исходящие действия. Не повторяйте предупреждение перед каждым чтением или уже согласованной разовой отправкой.

## Что делает первая версия

- Один разрешённый личный диалог на экземпляр: числовой ID задаётся владельцем при настройке и отсутствует в параметрах инструментов рабочего агента.
- `guard_read` читает до 30 последних сообщений этого диалога. Все тексты и имена остаются недоверенными данными, включая сообщения с утверждениями «я владелец» и поддельными системными ролями.
- Свободный ответ через `guard_propose_reply` становится черновиком. В MCP нет команды утверждения черновика или изменения политики. Владелец рассматривает конкретный текст в отдельном доверенном интерфейсе/Terminal.
- Утверждение связано с точными получателем, текстом, ответом на сообщение, экземпляром политики, временем и сроком действия. Изменение параметров или повторное использование не дают новой отправки.
- Необязательные автоответы — только неизменные шаблоны владельца, без подстановки текста собеседника, адресов, ссылок и файлов. Они включаются отдельно.
- У исходящего действия должен быть уже прочитанный входящий исходник. На одно входящее допускается не более одной попытки отправки. Проверяются срок, общий бюджет и отзыв делегирования.
- Неопределённая отправка не повторяется автоматически. Для статуса `sent` требуется чтение с сервера и совпадение текста, исходного сообщения и исходящего ID.
- После асинхронной подготовки, непосредственно перед записью в Telegram повторно проверяются срок действия и отзыв. Если разрешение закрыто до начала записи, действие отклоняется и отправки нет.

Локальные эвристики отмечают некоторые подозрительные формулировки. Это подсказки: отсутствие отметки не означает безопасность, а наличие не блокирует нормальную цитату. Решение о доступе не зависит от эвристик.

## Обязательная граница рабочего агента

Guard ограничивает только действия, проходящие через него. **Он не превращает обычный Codex/Claude-чат с полными правами в изолированного агента.**

Рабочему агенту доступны только инструменты этого экземпляра Guard. У него не должно быть исходного Telegram MCP, терминала, чтения файлов, других MCP, произвольного HTTP/браузера или доступа к файлам политики, очереди, авторизации и сессии. Интерфейс также не должен автоматически загружать внешние картинки/URL из ответа модели. Администраторский канал утверждений остаётся вне рабочего агента.

Настройка MCP не обеспечивает эти ограничения хоста. v0 не проверяет их автоматически и возвращает `host_isolation_verified: false`. При доступе к тому же файловому хранилищу или обходным инструментам модель может обойти брокер. Разные каталоги под одним пользователем ОС сами по себе не являются изоляцией.

## Проверить прототип без аккаунта

После обычной установки зависимостей:

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python verify_guard.py
```

Сквозной тест запускает настоящий защищённый MCP, отдельный искусственный upstream и отдельную команду владельца. Сетевые сокеты искусственного Telegram запрещены. Тест не входит в Telegram, не читает реальные диалоги и не отправляет настоящие сообщения.

## Настройка владельцем

Для первой проверки используйте искусственный backend из `verify_guard.py`. Для реального пилота сначала подготовьте действительно ограниченный клиент/worker и выберите контакт в доверенном интерфейсе. Не выдавайте доступ по ID или имени, предложенному собеседником внутри переписки.

Пример команды после согласования режима и реального числового ID:

```bash
.venv/bin/python -m telegram_setup.conversation_guard --home /absolute/operator/guard-contact init \
  --chat-id 12345 --hours 4 --budget 10 --read-budget 240 --acknowledge-risk
```

`12345` здесь — синтетический пример, не готовый получатель. Команда показывает предупреждение. `--acknowledge-risk` подтверждает ознакомление, а не доказанную изоляцию. Без этого флага политика не создаётся. Повторный `init` не перезаписывает существующую политику.

По умолчанию upstream — уже настроенный `server.py` этой установки. У него должны быть разрешены чтение и `reply_to_message`; Guard сам не расширяет права. Можно указать другую существующую stdio-команду через `--upstream-command`, повторяемый `--upstream-arg` и `--upstream-cwd`. Для общего backend используйте его лёгкий MCP-клиент, не новый Telethon/login. Не запускайте два владельца одной Telegram-сессии.

Пример регистрации для **отдельного ограниченного клиента**: [guarded-mcp-config.toml](../examples/guarded-mcp-config.toml). Рабочий корень агента не должен включать `/absolute/operator/guard-contact`.

Для неизменных автоответов добавьте при `init`:

```bash
--templates-file examples/guard-templates.json
```

Перед применением владелец читает и выбирает тексты. [Пример шаблонов](../examples/guard-templates.json) не подключается автоматически. Режима автоматической отправки произвольных сгенерированных ответов в v0 нет.

## Инструменты рабочего агента

| Инструмент | Результат |
|---|---|
| `guard_status` | Границы диалога, срок, бюджеты, состояние отправителя |
| `guard_read` | Сообщения одного диалога с маркировкой недоверенного содержимого |
| `guard_propose_reply(in_reply_to, text)` | Черновик, без утверждения и отправки |
| `guard_get_draft(action_id)` | Статус черновика/отправки, без повтора |
| `guard_request_template(in_reply_to, template_id)` | Только при явно заданных шаблонах; ставит точный текст в очередь |

Неизвестные инструменты и лишние параметры отклоняются. Обычные `send_file`, `send_message`, экспорт других чатов, удаление, смена аккаунта, управление политикой и запуск команд не публикуются и не перенаправляются upstream.

## Рассмотреть и утвердить черновик

Это команды **доверенного владельца**, не инструменты рабочего агента:

```bash
.venv/bin/python -m telegram_setup.conversation_guard --home /absolute/operator/guard-contact review ACTION_ID
.venv/bin/python -m telegram_setup.conversation_guard --home /absolute/operator/guard-contact approve ACTION_ID --sha256 ACTION_HASH
.venv/bin/python -m telegram_setup.conversation_guard --home /absolute/operator/guard-contact reject ACTION_ID
.venv/bin/python -m telegram_setup.conversation_guard --home /absolute/operator/guard-contact revoke
```

В `review` проверьте `chat_id`, `message_id`, полный `text`, срок и `hash`. Утверждение — запись в защищённом хранилище; хеш связывает содержание действия, но **не является секретом или самостоятельной аутентификацией владельца**. Доступ к операторской команде и хранилищу обеспечивает хост.

Работающий процесс Guard забирает утверждённое действие, атомарно расходует разрешение и проверяет доставку. `approve` означает утверждение, а не доставку. После него проверяйте `guard_get_draft`: `pending`, `approved`, `sending`, `sent`, `rejected` либо `uncertain_do_not_retry`. Отзыв останавливает новые действия; уже начавшаяся запись в Telegram может завершиться. Отклонённая до записи попытка также не возобновляется автоматически и сохраняет резерв бюджета.

Политика и SQLite-очередь хранятся локально с правами 600, каталог — 700. Очередь содержит тексты черновиков, поэтому она также приватная. Это файловая защита, не шифрование.

## Границы проверки

Проверены правила и исполнение при искусственно скомпрометированном поведении рабочего агента. Это не измерение устойчивости конкретной LLM к prompt injection и не проверка полноценной изоляции хоста.

v0 поддерживает текстовые ответы в одном личном диалоге. Группы, темы, вложения/OCR, голосовые, свободные автоответы, несколько аккаунтов и перенос состояния между мессенджерами требуют отдельных адаптеров и тестов. Семантически вредный черновик всё ещё может убедить невнимательного проверяющего; опасный текст может попасть и в обычный ответ модели. Ограничивайте доступный ей контекст и интерфейс отображения.

Брокер и очередь не зависят от Telegram. Telegram-адаптер использует `get_history` и `reply_to_message`; это даёт основу для других мессенджеров, но не подтверждает их готовую поддержку.
